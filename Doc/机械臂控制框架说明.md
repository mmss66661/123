# 机械臂控制框架说明（RobotArm/）

六轴机械臂控制框架，分层架构参考[稚晖君 Dummy-Robot](https://github.com/peng-zhihui/Dummy-Robot)
的 Robot 核心库设计，执行层直接对接本工程现有的达妙(DM)电机 CAN 接口。

**当前状态：代码已就绪、已通过上位机数值验证与固件编译；DH 参数与关节零位
还是占位值，实测填入 `RobotArm/Inc/arm_config.h` 后笛卡尔控制即可启用。**

## 1. 分层架构

```
armTask (FreeRTOS 任务, Task/Src/armTask.cpp)
   │  HMI/应用层入口
   ▼
ArmController (RobotArm/Src/arm_controller.cpp)      ← 状态机/指令队列/安全监控
   │  moveJ / moveJQueue / moveCartesian / jog / setGripper
   ├──────────────┐
   ▼              ▼
trajectory    kinematics                            ← 纯算法，无硬件依赖
(同步梯形MoveJ)  (DH正解 + LM数值逆解)
   │
   ▼
ArmHal (RobotArm/Src/arm_hal_dm.cpp)                 ← 执行器抽象层
   │  达妙电机使能/命令/反馈、差速腕耦合、夹爪 PWM
   ▼
bsp_can / DM_motor_J0~J5 / htim1（现有代码）
```

| 模块 | 文件 | 对应 Dummy-Robot |
|------|------|------------------|
| 参数总表 | `RobotArm/Inc/arm_config.h` | DH 参数 + 关节配置注入 DummyRobot 类 |
| 运动学 | `RobotArm/Src/kinematics.cpp` | Kinematics（Dummy 为球腕闭式解，本框架为 LM 数值解） |
| 轨迹规划 | `RobotArm/Src/trajectory.cpp` | MoveJ 同步梯形（最大行程关节定节拍） |
| 控制器 | `RobotArm/Src/arm_controller.cpp` | DummyRobot 状态机 + SEQ/INT 命令模式 |
| 执行抽象 | `RobotArm/Src/arm_hal_dm.cpp` | 随动舵机驱动（CAN 命令/广播同步） |

## 2. 关节-电机映射（现状，ID 为实测值）

| 运动学关节 | 含义 | 电机 | CAN ID | 软件限位 (rad) | 备注 |
|-----------|------|------|:------:|----------------|------|
| q0 | 底部 yaw | DM | 0x02 | 1.727 ~ 5.405 | 已实测 |
| q1 | 底部 pitch | DM | 0x03 | 1.050 ~ 2.278 | 已实测 |
| q2 | 中段 | DM | 0x04 | 0.003 ~ 1.849 | 已实测 |
| q3 | 末端 yaw | DM | 0x05 | 无 | — |
| q4 | 腕 roll | DM×2 共模 | 0x06+0x07 | 无 | **[未测量]** 传动比例占位 0.5 |
| q5 | 腕 pitch | DM×2 差模 | 0x06+0x07 | -2.081 ~ 2.838 | 差模即现有 m4−m5 定义 |

差速腕换算（全部在 ArmHal 层完成，控制器只见 q4/q5）：

```
roll  = kWristRollGain  * ((m4 - kWristM4Zero) + (m5 - kWristM5Zero))
pitch = kWristPitchGain * ((m4 - kWristM4Zero) - (m5 - kWristM5Zero))
```

J0~J3 单电机关节：`q = direction * (motor_pos - zero_offset)`。

## 3. 快速上手

1. **切换任务**：`Core/Src/freertos.c` 中注释掉 `MotorTask_Init()`，取消
   `ArmTask_Init()` 的注释。两者驱动同一组电机，**不能同时运行**。
   框架上电处于 Disabled，不主动发任何命令。
2. 编译：`cmake --build build/Debug`（已加入 CMake，无需其它改动）。
3. 调用示例（armTask::run 或任意任务中）：

```cpp
using arm::armController;

armController.enable(HAL_GetTick());            // 轮询反馈并在当前位置使能保持

float q[6] = {3.57f, 1.66f, 0.93f, 0, 0, 0.38f};
armController.moveJ(q, HAL_GetTick());          // INT：立即打断当前轨迹
armController.moveJQueue(q, HAL_GetTick());     // SEQ：排队依次执行
armController.jog(1, +0.05f, HAL_GetTick());    // 单关节点动
armController.setGripper(true);                 // 夹爪闭合

arm::Pose p{0.25f, 0.0f, 0.30f, 0, 0, 0};       // x/y/z(m) + roll/pitch/yaw(rad)
armController.moveCartesian(p, HAL_GetTick());  // 需先完成 DH 标定（见下节）

armController.disable(HAL_GetTick());           // 失能/急停
```

4. 调试变量（调试器 Live Watch）：

| 变量 | 含义 |
|------|------|
| `arm_fw_state` | 0失能 1就绪 2运动中 3故障 |
| `arm_fw_fault` | 0无 1反馈超时 2电机报码 3CAN发送 4跟踪超时 5超限位 |
| `arm_fw_request` | 最近请求结果：0成功 1未使能 2未标定 3IK失败 4目标非法 5队列满 |
| `arm_fw_ik_iters / ik_err_pos / ik_err_rot` | 最近一次 IK 迭代数与残差 |
| `arm_fw_traj_progress` | 当前轨迹进度 0~1 |
| `arm_fw_tracking_err` | 最大关节跟踪误差 rad |

## 4. 参数测量与标定流程（填 arm_config.h）

### 4.1 关节零位（kJoints[].zero_offset / kWristM4Zero/M5Zero）

1. 断电状态下把机械臂摆到"定义零位"（建议各关节取限位中点附近、末端朝前的
   自然姿态，记录照片留档）。
2. 上电后不使能，在调试器读 `DM_motor_J0..J5.pos`（或跑一次
   `hal::pollFeedback`）。
3. 把六个读数填入 `zero_offset`（腕部两台填 `kWristM4Zero/kWristM5Zero`）。
4. 验证：`armController` Disabled 态下 `arm_fw_*` 正常，使能后
   `getCurrentJoints()` 输出接近全零。

### 4.2 方向 direction

使能后点动 `jog(i, +0.1f)`，确认关节 i 沿"运动学正方向"（自定约定，建议
与 DH 推导时一致）转动；不对则把该关节 `direction` 改为 -1。

### 4.3 DH 参数（kDh[]，单位 m / rad）

**方法 A（推荐）：从 CAD 提取轴线，脚本自动算 DH**

数学模型 = 零位姿态下的六条关节轴线（一点 + 一方向），工具已备好：

1. `tools/fusion_export_axes.py`：Fusion 360 脚本（Utilities → ADD-INS →
   Scripts → 新建 Python 粘贴）。模型摆到零位后运行，依次点选 J0~J5 的
   关节轴线（圆形边/圆柱面/直边/构造轴）和 TCP 点，自动打印世界坐标(mm)。
2. 把输出粘到 `tools/dh_from_axes.py` 的 `AXES_MM`，运行即得 `kDh[]`
   片段（含公垂线法自动处理平行/相交/共线轴线，并自带往返校验，
   精度 1e-16）。
3. 只有 STEP 时：用 FreeCAD 打开，量出六条轴线（过点 + 方向）填入
   `AXES_MM` 即可，计算完全相同。STL 只有网格，不要用来标定。

注意：轴线方向 = 关节运动学正方向（选反了把该方向取负重跑）；
CAD 给的是名义模型，`theta_offset` 对应 CAD 零位，电机零位仍按 4.1 实测；
差速腕的 `kWristRollGain/kWristPitchGain` 需查 CAD 齿轮比或实测。

**方法 B：手工测量（无 CAD 时）**

用卷尺/卡尺测量（对应标准 DH：A_i = Rz(θ)·Tz(d)·Tx(a)·Rx(α)）：

- `d`：沿关节轴方向的有效长度（如基座到 J1 轴线的竖直距离）；
- `a`：相邻关节轴线的公垂线长度（轴心距）；
- `alpha`：相邻关节轴线的夹角（平行为 0，垂直为 ±π/2，符号按右手系试凑，
  用 FK 输出对照实测末端位置验证）；
- `theta_offset`：零位摆好后各关节的剩余偏差（零位标定正确后多为 0）。

**验证方法**：零位标定后手动摆几个姿态，用 `solveFkPose()` 算末端坐标，
与卷尺实测末端位置对比，偏差应 < 1 cm 量级；反复修正 alpha 符号与 d/a 直到
吻合。全部完成后把 `kDhParamsMeasured` 改为 `true`，`moveCartesian` 生效。

### 4.4 差速腕增益 kWristRollGain

固定 pitch（两电机同向转动 Δ 圈），量末端 roll 变化角，`增益 = roll角/电机角`。
`kWristPitchGain` 当前按 m4−m5 直取 1.0，与现有手动控制一致。

## 5. 算法验证（上位机，无硬件）

`test/verify_kinematics.py` 直接解析 `arm_config.h` 里的**实际参数**做验证：

```
python test/verify_kinematics.py
```

- DH 正解与手工推导核对、解析雅可比 vs 有限差分（<1e-10）
- IK 邻近种子(±0.4 rad，真实工况) 60/60 收敛，最差 0.73 mm
- IK 随机种子(跨位形严苛场景) ~90% 收敛；不可达目标正确报失败
- 梯形轨迹边界/单调性/速度限幅 200 组

参数修改后建议先跑一遍再上机。

## 6. 控制器行为与安全

- **状态机**：Disabled → (enable, 在当前位置使能) → Ready → (moveJ) → Moving
  → (到位: 全关节误差 < 0.04 rad 持续 300 ms) → Ready；任何态可 disable。
- **故障即失能锁存**：反馈超时 100 ms、电机报码(状态 8~E)、CAN 连续 3 帧
  失败、跟踪暂停超 3 s、轨迹点超软限位 → 立即全部失能，`disable()` 清锁存。
- **跟踪暂停**（沿用回放逻辑）：误差 > 0.35 rad 时冻结轨迹时间轴，追上后
  继续沿用原时间标尺。
- **命令模式**：`moveJ` 立即打断（从当前指令角重新规划，无跳变）；
  `moveJQueue` 深度 8 顺序执行。
- MoveJ 全关节同起同止（最大行程关节按 1.0 rad/s、2.5 rad/s² 定节拍，
  见 `kTrajDefaultVel/Acc`）。

### 首次上机顺序（与录制回放测试同样保守）

1. 卸载/悬空机械臂，急停触手可及；
2. 上电等 2 秒（达妙初始化延时），确认 `arm_fw_state == 0`；
3. `enable()` 后先只做小角度 `jog`，确认六个关节方向正确；
4. 再试小范围 `moveJ`（各关节离限位 > 0.3 rad），观察跟踪误差
   `arm_fw_tracking_err` 应 < 0.05 rad；
5. 标定完成前不要调用 `moveCartesian`（框架会拒绝并置 `arm_fw_request=2`）。

## 7. 已知限制与扩展方向

- **IK 为数值解**：任意构型通用，但跨位形远距离目标可能返回 `IkFailed`
  （此时可拆成中间路点）。DH 确定且构型为标准球腕后，可按 Dummy-Robot 的
  Pieper 闭式解重写 `solveIk`（接口不变，选解策略同样取最小关节变化量）。
- **MoveL（笛卡尔直线插补）** 未实现：可在控制器层按 20~50 Hz 插补位姿 +
  逐点 `solveIk` 实现，接口位置已预留。
- **双臂**：每条臂实例化一个 `ArmController`（HAL 需按 CAN ID 区分），
  当前 `armController` 单例对应 CAN1 上的六电机臂。
- J1 的 MIT 阻抗模式未接入本框架（沿用手动控制经验值 kp=50/kd=0.3 可在
  ArmHal 层扩展）。
